## 2. 개발 목적

사이트에 게시된 유튜브 영상을 로그인 회원이 시청하면 다음 기능을 제공한다.

1. 영상 아래에 현재 시청률을 `0~100%`로 표시한다.
2. 게시물 목록에서도 회원이 마지막으로 저장한 시청률을 확인할 수 있게 한다.
3. 여러 번 나누어 시청해도 이전 시청 구간과 합산한다.
4. 진행 막대를 드래그하거나 15초를 초과해 앞으로 건너뛴 구간은 시청한 것으로 계산하지 않는다. 방향키의 15초 이하 짧은 이동은 연속 시청으로 반영한다.
5. 시청률이 관리자가 지정한 캘린더 등록 기준에 처음 도달하면 회원의 `내 캘린더`에 자동으로 일정을 등록한다.
6. 같은 회원과 같은 영상의 완료 일정을 중복 등록하지 않는다.

이 기능은 유튜브 계정의 전체 시청 기록을 가져오는 기능이 아니다. 사이트 내부에 삽입된 플레이어에서 재생한 구간만 기록한다.

## 3. 현재 시스템 분석

### 3.1 유튜브 게시물

- UXC 게시판 스킨은 주로 게시물의 `wr_10`에 유튜브 URL을 저장한다.
- 게시물 상세 스킨은 현재 `youtube.com/embed/{video_id}` iframe을 직접 출력한다.
- 블로그 목록 스킨에서도 iframe으로 영상을 재생할 수 있다.
- `pic_plyr_block` 최신글 스킨은 `wr_link1`의 영상 주소와 Plyr 3.7.8을 사용한다.
- 여러 게시판 스킨에 유튜브 ID 추출 및 iframe 출력 코드가 중복되어 있다.
- 현재 iframe에는 시청 상태를 읽기 위한 `enablejsapi=1` 설정과 공통 추적 모듈이 없다.

1차 적용 대상은 다음과 같다.

| 구분 | 경로 또는 패턴 | 비고 |
| --- | --- | --- |
| 게시물 상세 | `theme/UXC_BaseCamp/skin/board/uxc_*/view.skin.php` | `wr_10` 기반 iframe |
| 블로그 목록 | `theme/UXC_BaseCamp/skin/board/uxc_blog*/list.skin.php` | 목록에서 직접 재생 가능 |
| 최신글 플레이어 | `skin/latest/pic_plyr_block/latest.skin.php` | `wr_link1`, Plyr 사용 |
| 테마 최신글 플레이어 | `theme/basic/skin/latest/pic_plyr_block/latest.skin.php` | 위 스킨의 테마 복사본 |

개발 착수 시 운영 중인 게시판의 실제 스킨 설정을 조회해 적용 대상 목록을 확정한다. 썸네일만 출력하고 상세 페이지로 이동하는 목록은 상태 배지만 표시하고 플레이어 추적은 하지 않는다.

### 3.2 개인 캘린더

- `plugin/wz.calendar`에 회원별 일정 등록·수정·삭제 API가 구현되어 있다.
- 모든 일정은 세션의 `mb_id`를 기준으로 분리된다.
- 일정에는 제목, 날짜, 시간, 메모, 링크를 저장할 수 있다.
- 회원당 일정 최대 개수 제한과 CSRF 검사가 적용되어 있다.
- 현재 일정 테이블에는 유튜브 게시물과의 연결 정보를 직접 저장하는 컬럼이 없다.

기존 일정 저장 API를 브라우저에서 다시 호출하는 방식보다 캘린더 라이브러리에 내부용 일정 생성 함수를 만들고 시청 완료 처리에서 재사용한다. 이렇게 해야 일정 검증, 최대 개수 제한, 날짜별 정렬 처리를 한곳에서 유지할 수 있다.

## 4. 확정 기능 범위

### 4.1 포함 범위

- 로그인 회원의 게시물별 유튜브 시청 상태 저장
- 한 게시물에 연결된 대표 유튜브 영상 1개 추적
- 재생, 일시정지, 탐색, 종료 이벤트 처리
- 시청한 영상 구간을 합산한 시청률 계산
- 상세 화면의 실시간 시청률과 진행 막대
- 목록 화면의 저장된 시청률 배지
- 완료 기준 최초 도달 시 개인 캘린더 일정 자동등록
- 회원·게시물·유튜브 영상별 중복 방지
- PC와 모바일 브라우저 지원
- 관리자 기능 사용 여부, 방향키 반영 여부, 완료 기준과 캘린더 등록 기준 설정

### 4.2 제외 범위

- 유튜브 사이트나 유튜브 앱에서 본 영상 기록 가져오기
- 유튜브 계정의 Watch History 연동
- 비회원의 서버 영구 저장 및 캘린더 등록
- Vimeo 등 유튜브 이외 제공자의 시청률 추적
- 실시간 방송과 종료되지 않은 라이브 스트림
- 게시물 본문 안에 임의로 삽입된 복수 iframe 자동 탐색
- Google Calendar, Outlook 등 외부 캘린더 동기화
- 시청률을 포인트·수료증·법적 이수 증빙으로 사용하는 기능

## 5. 시청률 산정 규칙

### 5.1 기본 산식

```text
시청률(%) = floor(중복을 제거한 실제 시청 구간의 초 합계 / 영상 전체 길이 × 100)
```

- 결과는 `0~100` 범위의 정수로 표시한다.
- 영상 길이는 플레이어가 준비된 후 YouTube API 또는 Plyr의 `duration` 값으로 구한다.
- `duration`이 0이거나 정상적인 고정 길이를 구할 수 없는 영상은 시청률 저장과 자동등록 대상에서 제외한다.
- 영상 재생 위치인 `currentTime / duration`만으로 계산하지 않는다. 이 방식은 영상 끝으로 건너뛰었을 때 보지 않은 구간까지 시청한 것으로 잘못 표시하기 때문이다.

### 5.2 시청 구간 수집

재생 중 1초 단위로 로컬 상태를 갱신하고 10초마다 서버에 합쳐 저장한다.

예를 들어 회원이 `0~30초`를 본 뒤 `60초`로 이동해 `60~90초`를 봤다면 저장 구간은 다음과 같다.

```json
[[0, 30], [60, 90]]
```

전체 길이가 100초라면 시청률은 60%다. 이후 `25~70초`를 시청하면 겹치는 범위를 병합해 `0~90초`가 되고 시청률은 90%가 된다.

구간 처리 규칙은 다음과 같다.

- 정상 재생 중 연속해서 진행한 구간만 추가한다.
- `seeking`이 시작되면 현재 구간을 닫고 `seeked` 후 새 구간을 시작한다.
- 방향키 사용을 고려해 15초 이하의 짧은 앞으로 탐색은 직전 구간에 이어진 시청으로 합산한다.
- 15초를 초과하는 앞으로 탐색과 진행 막대의 큰 구간 이동은 시청 구간에서 제외한다.
- 이미 시청한 구간을 다시 보면 퍼센트가 중복 증가하지 않는다.
- 재생 속도 변경은 허용한다. 실제 플레이어 타임라인에서 지나간 콘텐츠 구간을 기록한다.
- 일시정지, 버퍼링, 탭이 숨겨진 상태에서는 재생 구간을 임의로 증가시키지 않는다.
- 비정상적으로 큰 위치 이동은 서버에서도 잘라내거나 거부한다.
- 저장 구간은 인접 구간을 병합하고 개수 상한을 둬 데이터가 과도하게 커지지 않게 한다.

클라이언트 JavaScript는 사용자가 조작할 수 있으므로 이 수치는 일반 편의 기능으로 취급한다. 시험 수료나 보상 지급처럼 부정 사용 방지가 중요한 용도로 확장하려면 별도의 검증 체계가 필요하다.

### 5.3 저장 시점

- 최초 재생 시작
- 재생 중 10초 간격
- 일시정지
- 탐색 시작 직전
- 영상 종료
- 페이지 이탈 또는 백그라운드 전환
- 마지막 저장 이후 시청률 정수가 변경된 경우

페이지 이탈 시에는 `fetch(..., {keepalive: true})`를 우선 사용한다. 전송 실패가 발생하면 미전송 구간을 `sessionStorage`에 잠시 보관하고 같은 게시물을 다시 열었을 때 재시도한다.

### 5.4 완료 판정

- 기본 완료 기준은 실제 시청 구간 90%다.
- 관리자 설정에서 50~100% 범위로 변경할 수 있게 한다.
- 단순히 YouTube의 `ENDED` 이벤트가 발생했다는 이유만으로 완료 처리하지 않는다. 영상 끝으로 탐색한 경우를 막기 위해 저장된 시청 구간이 완료 기준 이상이어야 한다.
- 완료 시각은 클라이언트 시간이 아닌 서버의 `NOW()`를 사용한다.
- 한 번 완료된 기록은 이후 시청률 계산 방식이나 기준값이 바뀌어도 자동으로 미완료로 되돌리지 않는다.

## 6. 화면 및 사용자 경험

### 6.1 영상 상세 화면

플레이어 아래에 다음 정보를 표시한다.

```text
시청률 42%                            4분 12초 / 10분 00초
[█████████████████░░░░░░░░░░░░░░░░░░░░░░░░░]
```

- 접근 가능한 `<progress>` 요소와 텍스트 퍼센트를 함께 사용한다.
- 진행 막대의 `aria-label` 또는 연결된 설명에 현재 시청률을 제공한다.
- 서버에 저장되지 않은 최근 재생 구간도 화면에는 즉시 반영한다.
- 저장 성공 후 `저장됨`, 네트워크 오류 시 `저장 대기 중` 상태를 짧게 표시한다.
- 완료 기준에 도달하면 `시청 완료 · 캘린더 등록됨`을 표시한다.
- 캘린더가 꺼져 있거나 한도 초과로 등록되지 못한 경우 `시청 완료 · 캘린더 등록 대기`를 표시한다.
- 로그아웃 상태에서는 시청률 영역 대신 `로그인하면 시청률을 저장할 수 있습니다.`를 표시하거나 설정에 따라 영역을 숨긴다.

### 6.2 게시물 목록

- 현재 페이지에 출력된 게시물 ID를 한 번의 배치 상태 조회 API로 요청한다.
- 각 유튜브 게시물 카드에 `미시청`, `시청 중 42%`, `시청 완료` 배지를 표시한다.
- 목록의 플레이어에서 직접 재생 가능한 경우 같은 공통 추적 모듈을 연결한다.
- 영상이 없는 게시물에는 배지를 출력하지 않는다.
- 페이지마다 개별 상태 API를 여러 번 호출하는 N+1 요청을 만들지 않는다.

### 6.3 개인 캘린더

관리자가 설정한 캘린더 자동등록 시청률에 최초 도달한 날짜에 종일 일정 1개를 생성한다.

| 일정 필드 | 저장 값 |
| --- | --- |
| 제목 | 완료 전 등록은 `[{등록 당시 퍼센트}% 시청]`, 완료 후 등록은 `[시청완료]` + 게시물 제목 |
| 시작일·종료일 | 등록 기준에 도달한 서버 날짜 |
| 종일 일정 | 예 |
| 분류 | 없음 또는 추후 회원이 선택한 기본 분류 |
| 메모 | 등록 당시 시청률, 등록 시각, 영상 식별 정보 |
| 링크 | 원본 게시물의 사이트 내부 URL |

- 제목은 HTML을 제거하고 캘린더 제목 최대 길이에 맞춰 자른다.
- 게시물 제목과 URL은 클라이언트가 보낸 값을 사용하지 않고 서버가 게시물 테이블에서 다시 조회한다.
- 게시물 제목이 나중에 바뀌더라도 이미 등록된 일정은 시청 당시의 제목을 유지한다.
- 자동 생성된 일정을 회원이 삭제하면 다시 영상을 재생해도 자동으로 되살리지 않는다.
- 캘린더 일정 최대 개수 초과, 기능 비활성화 등의 경우에도 시청 기록은 보존하고 일정 상태만 `등록 대기` 또는 `등록 불가`로 남긴다.

## 7. 데이터베이스 설계

새 플러그인의 테이블 접두사는 예시로 `wzy`를 사용한다.

### 7.1 시청 기록 테이블 `g5_wzy_watch`

| 컬럼 | 형식 | 설명 |
| --- | --- | --- |
| `ww_ix` | BIGINT, PK, AI | 시청 기록 ID |
| `mb_id` | VARCHAR(20), INDEX | 회원 ID |
| `bo_table` | VARCHAR(20) | 게시판 ID |
| `wr_id` | BIGINT | 원본 게시물 ID |
| `wy_video_id` | VARCHAR(20) | 검증된 YouTube 영상 ID |
| `ww_subject_snapshot` | VARCHAR(255) | 완료 또는 마지막 저장 당시 제목 |
| `ww_duration_seconds` | DECIMAL(12,3) | 확인된 전체 영상 길이 |
| `ww_ranges_json` | MEDIUMTEXT | 병합된 시청 구간 JSON |
| `ww_watched_seconds` | DECIMAL(12,3) | 중복 제거된 시청 초 합계 |
| `ww_percent` | TINYINT UNSIGNED | 마지막 계산 시청률 |
| `ww_last_position` | DECIMAL(12,3) | 마지막 정상 재생 위치 |
| `ww_status` | ENUM 또는 VARCHAR(20) | `watching`, `completed` |
| `ww_started_at` | DATETIME | 최초 시청 시각 |
| `ww_last_watched_at` | DATETIME | 마지막 시청 시각 |
| `ww_completed_at` | DATETIME NULL | 최초 완료 시각 |
| `ww_calendar_event_id` | BIGINT NULL | 자동 생성된 캘린더 일정 ID |
| `ww_calendar_status` | VARCHAR(20) | `none`, `pending`, `created`, `unavailable`, `deleted` |
| `ww_version` | INT UNSIGNED | 동시 저장 충돌 방지 버전 |
| `ww_created_at` | DATETIME | 생성 시각 |
| `ww_updated_at` | DATETIME | 수정 시각 |

필수 키는 다음과 같다.

```sql
UNIQUE KEY member_post_video (mb_id, bo_table, wr_id, wy_video_id)
KEY member_recent (mb_id, ww_last_watched_at)
KEY calendar_event (ww_calendar_event_id)
```

고유 키와 트랜잭션으로 여러 탭이나 재시도 요청이 동시에 들어와도 시청 기록과 캘린더 일정이 하나만 생성되게 한다.

## 8. 서버 API 설계

새 플러그인 경로 예시는 다음과 같다.

```text
plugin/wz.youtube_watch/
├── _common.php
├── config.php
├── youtube_watch.lib.php
├── ajax.watch.status.php
├── ajax.watch.progress.php
├── youtube-watch.js
├── style.css
└── admin/
    ├── install.php
    └── config.php
```

### 8.1 상태 일괄 조회

```http
POST /plugin/wz.youtube_watch/ajax.watch.status.php
Content-Type: application/json
```

요청 예시:

```json
{
  "csrf_token": "...",
  "bo_table": "free",
  "wr_ids": [10, 11, 12]
}
```

응답 예시:

```json
{
  "success": true,
  "items": {
    "10": {"percent": 42, "status": "watching"},
    "11": {"percent": 100, "status": "completed"}
  }
}
```

- 한 요청의 `wr_ids` 개수를 제한한다.
- 현재 회원에게 읽기 권한이 있는 게시물만 반환한다.
- 다른 회원의 시청 기록은 어떤 경우에도 반환하지 않는다.

### 8.2 진행률 저장

```http
POST /plugin/wz.youtube_watch/ajax.watch.progress.php
Content-Type: application/json
```

요청 예시:

```json
{
  "csrf_token": "...",
  "bo_table": "free",
  "wr_id": 10,
  "video_id": "abcdefghijk",
  "duration": 600.0,
  "ranges": [[120.0, 130.2]],
  "last_position": 130.2,
  "player": "youtube_iframe"
}
```

응답 예시:

```json
{
  "success": true,
  "percent": 42,
  "watched_seconds": 252,
  "duration": 600,
  "status": "watching",
  "calendar_status": "none"
}
```

완료된 경우:

```json
{
  "success": true,
  "percent": 90,
  "status": "completed",
  "completed_now": true,
  "calendar_status": "created",
  "calendar_event_id": 381
}
```

서버 처리 순서는 다음과 같다.

1. POST, 로그인, CSRF, 호출 빈도를 검사한다.
2. `bo_table` 허용 형식과 실제 게시판 존재 여부를 검사한다.
3. 게시물 테이블에서 `wr_id`, 제목, 공개 범위, 유튜브 URL을 조회한다.
4. 회원이 해당 게시물을 읽을 수 있는지 확인한다.
5. 서버가 추출한 영상 ID와 요청의 영상 ID가 같은지 확인한다.
6. duration과 각 구간의 숫자 형식, 범위, 최대 길이를 검증한다.
7. 기존 구간과 새 구간을 병합하고 시청률을 서버에서 다시 계산한다.
8. 버전과 행 잠금을 사용해 동시 요청을 병합한다.
9. 완료 기준을 처음 넘었으면 완료 상태와 완료 시각을 저장한다.
10. 캘린더 일정 생성 조건을 확인하고 멱등 방식으로 일정 1개를 생성한다.
11. 서버가 계산한 최신 상태를 응답한다.

## 9. 플레이어 연동 설계

### 9.1 직접 iframe을 사용하는 스킨

- iframe URL에 `enablejsapi=1`과 현재 사이트의 `origin`을 추가한다.
- 각 플레이어에 중복되지 않는 DOM ID와 게시판·게시물·영상 식별용 `data-*` 속성을 부여한다.
- YouTube IFrame Player API 스크립트는 페이지당 한 번만 비동기로 불러온다.
- 전역 `onYouTubeIframeAPIReady`를 덮어쓰지 않고 공통 로더에서 대기 중인 플레이어를 모두 초기화한다.
- `onReady`, `onStateChange`, `getCurrentTime()`, `getDuration()`을 공통 추적 어댑터에 연결한다.

### 9.2 Plyr를 사용하는 스킨

- 기존 `Plyr.setup()` 결과의 각 인스턴스를 공통 추적 어댑터에 등록한다.
- Plyr의 `ready`, `playing`, `pause`, `timeupdate`, `seeking`, `seeked`, `ended` 이벤트를 사용한다.
- `player.currentTime`, `player.duration`, `player.playing`, `player.seeking`을 공통 형식으로 변환한다.
- 다른 영상을 재생할 때 기존 영상을 일시정지하는 현재 동작은 유지한다.

### 9.3 공통 마크업

```html
<div class="wzy-player"
     data-wzy-bo-table="free"
     data-wzy-wr-id="10"
     data-wzy-video-id="abcdefghijk">
    <!-- YouTube 또는 Plyr 플레이어 -->
    <div class="wzy-progress-status" aria-live="polite">
        <span>시청률 <strong>42%</strong></span>
        <progress max="100" value="42">42%</progress>
    </div>
</div>
```

게시물 제목은 `data-*` 속성으로 전송하지 않는다. 필요하더라도 화면 표시에만 사용하고, 캘린더 등록용 제목은 서버에서 조회한다.

## 10. 캘린더 연동 설계

### 10.1 공통 서비스 함수

`plugin/wz.calendar/calendar.lib.php`에 브라우저 응답을 직접 종료하지 않는 내부용 함수를 추가한다.

```php
wzc_create_member_event($mb_id, array $event_data, array $source = array())
```

함수는 다음 결과를 반환한다.

```php
array(
    'success' => true,
    'event_id' => 381,
    'code' => 'CREATED'
)
```

- 기존 `ajax.event.save.php`도 이 함수를 사용하도록 리팩터링한다.
- 시청 완료 처리에서는 `source_type=youtube_watch`, `source_id=ww_ix`를 전달한다.
- 캘린더의 회원별 최대 일정 수, 날짜 검증, 링크 검증, 일정 순서 저장 규칙을 그대로 적용한다.
- 일정 생성과 시청 기록 연결은 가능한 범위에서 한 트랜잭션으로 처리한다.
- 캘린더가 설치되지 않았거나 꺼진 경우 시청 저장 자체는 실패시키지 않는다.

### 10.2 중복 및 재시도

- 시청 기록의 고유 키로 동일 영상 기록을 하나만 유지한다.
- `ww_calendar_event_id`가 있으면 새 일정을 만들지 않는다.
- 연결된 일정은 시청률 저장 시 `[숫자%]` 또는 `[시청완료]` 접두어만 최신 상태로 동기화하고, 회원이 수정한 제목 본문과 메모는 유지한다.
- 완료 직후 일정 생성에 실패하면 `ww_calendar_status=pending`으로 저장한다.
- 다음 진행 저장 요청 또는 별도 보정 작업에서 `pending`만 안전하게 재시도한다.
- 이미 생성된 캘린더 일정을 회원이 삭제한 경우는 사용자 의사를 존중해 재생성하지 않는다.

## 11. 보안 및 개인정보 보호

- 모든 영구 저장과 캘린더 등록은 로그인 회원에게만 제공한다.
- 상태 조회와 저장 요청 모두 CSRF 토큰과 동일 출처 자격 증명을 요구한다.
- 모든 SQL 조건에 현재 세션의 `mb_id`를 포함한다.
- `bo_table`, `wr_id`, `video_id`, duration과 ranges를 신뢰하지 않고 서버에서 검증한다.
- 비밀글과 접근 제한 게시판은 기존 게시물 읽기 권한과 동일하게 검사한다.
- 제목과 링크는 서버 원본을 사용하고 HTML·스크립트가 일정에 들어가지 않게 정제한다.
- API 호출 빈도와 한 번에 전송할 구간 수·본문 크기를 제한한다.
- 운영 로그에는 회원의 세부 시청 구간이나 게시물 제목을 기록하지 않는다.
- 관리자 통계가 필요하면 콘텐츠 제목 없이 전체 이용 회원 수와 완료 건수만 집계한다.
- 탈퇴 회원 데이터 처리 정책에 시청 이력 삭제를 포함한다.

## 14. 테스트 계획

### 14.1 시청률 계산

- 100초 영상의 처음 40초를 보면 40%로 저장된다.
- 0~30초와 60~90초를 보면 60%로 저장된다.
- 겹치는 구간을 다시 봐도 중복 증가하지 않는다.
- 0초에서 90초로 건너뛴 직후 90%가 되지 않는다.
- 일시정지와 버퍼링 시간은 시청 시간에 포함되지 않는다.
- 재생 속도를 바꿔도 실제 지나간 영상 구간을 기준으로 계산한다.
- 페이지를 나갔다 돌아와도 이전 시청 구간과 이어진다.
- 서로 다른 영상과 서로 다른 회원의 기록이 섞이지 않는다.

### 14.2 완료 및 캘린더

- 89%에서는 일정이 생성되지 않고 90%가 되는 순간 한 번 생성된다.
- 종료 이벤트가 발생해도 실제 시청 구간이 기준 미만이면 생성되지 않는다.
- 같은 완료 요청을 여러 번 전송해도 일정이 하나만 생성된다.
- 여러 탭에서 동시에 완료해도 일정이 하나만 생성된다.
- 일정 제목, 완료 날짜, 메모와 원문 링크가 올바르다.
- 캘린더에서 자동 일정을 삭제한 뒤 다시 재생해도 되살아나지 않는다.
- 캘린더가 비활성화되거나 일정 한도를 초과해도 시청률 저장은 유지된다.

### 14.3 권한 및 보안

- 비회원의 저장 요청은 401로 거절된다.
- CSRF 토큰 누락·불일치 요청은 403으로 거절된다.
- 회원 A가 회원 B의 상태를 조회하거나 변경할 수 없다.
- 읽을 수 없는 비밀글과 권한 제한 게시물은 존재 여부가 노출되지 않는다.
- 다른 게시물의 `video_id`를 조작해 저장할 수 없다.
- 비정상 duration, 음수, `NaN`, 지나치게 큰 구간 배열이 거절된다.
- 제목에 스크립트 문자열이 있어도 화면과 캘린더에서 실행되지 않는다.
- 호출 빈도 제한 초과 시 429를 반환한다.

### 14.4 화면 및 호환성

- Chrome, Edge, Firefox, Safari 최신 지원 버전에서 동작한다.
- Android Chrome과 iOS Safari에서 재생·일시정지·페이지 이탈 저장을 확인한다.
- 390px 모바일 화면에서 퍼센트와 진행 막대가 잘리지 않는다.
- 키보드와 스크린리더에서 진행률을 확인할 수 있다.
- 상세 iframe과 Plyr 최신글 플레이어가 같은 계산 결과를 만든다.
- 한 페이지에 영상이 여러 개 있어도 API 스크립트와 이벤트가 충돌하지 않는다.

## 15. 배포 및 롤백

### 15.1 배포 순서

1. 데이터베이스와 현재 파일을 백업한다.
2. 신규 시청 기록 테이블과 설정 테이블을 설치한다.
3. 서버 API와 캘린더 공통 생성 함수를 먼저 배포한다.
4. 관리자 설정의 기능 플래그를 끈 상태로 플레이어와 UI 코드를 배포한다.
5. 테스트 계정과 제한된 게시판에서 기능을 켜 통합 검증한다.
6. 오류율과 일정 중복 여부를 확인한 뒤 전체 게시판에 활성화한다.

### 15.2 롤백

- 우선 관리자 설정에서 시청률 추적과 캘린더 자동등록을 끈다.
- 플레이어는 추적 모듈이 없어도 기존 유튜브 재생이 가능해야 한다.
- 신규 테이블은 즉시 삭제하지 않고 보존해 복구 가능성을 남긴다.
- 자동 생성된 캘린더 일정은 회원 개인 데이터이므로 일괄 삭제하지 않는다.
- 명확한 운영 승인을 받은 경우에만 `ww_calendar_event_id`로 대상 일정을 식별해 별도 정리한다.

## 16. 완료 조건

다음 항목이 모두 충족되면 개발 완료로 판단한다.

- 로그인 회원이 상세 및 목록 플레이어에서 시청한 비율을 실시간으로 볼 수 있다.
- 새로고침하거나 다른 기기에서 접속해도 서버에 저장된 시청률이 표시된다.
- 건너뛴 구간과 중복 시청 구간이 시청률을 부당하게 증가시키지 않는다.
- 캘린더 자동등록 기준 도달 시 해당 날짜의 `내 캘린더`에 게시물 제목 일정이 한 번만 등록된다.
- 캘린더 일정에서 원본 게시물로 이동할 수 있다.
- 회원 간 시청 이력과 일정이 완전히 분리된다.
- 비밀글과 게시판 읽기 권한이 시청 API에도 동일하게 적용된다.
- 캘린더 장애가 영상 재생이나 시청률 저장을 중단시키지 않는다.
- PC와 모바일의 주요 브라우저 통합 테스트를 통과한다.

## 17. 참고 자료

- [YouTube IFrame Player API Reference](https://developers.google.com/youtube/iframe_api_reference)
- [YouTube Embedded Players and Player Parameters](https://developers.google.com/youtube/player_parameters)
- [Plyr 공식 저장소 및 API 문서](https://github.com/sampotts/plyr)

YouTube IFrame Player API는 플레이어 상태 이벤트와 `getCurrentTime()`, `getDuration()`을 제공한다. iframe을 JavaScript로 제어할 때는 `enablejsapi=1`과 사이트 `origin`을 사용한다. Plyr는 YouTube 플레이어에 대해 표준화된 재생 이벤트와 `currentTime`, `duration` 접근자를 제공하므로 두 플레이어 구현을 하나의 시청률 추적 어댑터로 통합할 수 있다.
