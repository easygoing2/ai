## 1. 확정된 개발 방향

- 로그인 회원만 캘린더에 접근한다.
- 회원은 자신의 일정과 분류만 조회·등록·수정·삭제한다.
- 다른 회원의 일정은 일반 화면과 관리자 통계 화면에 노출하지 않는다.
- 일정과 분류는 회원 ID인 `mb_id`로 완전히 분리한다.
- 일정 항목은 같은 날짜 안에서 드래그하여 순서를 변경할 수 있다.
- 일정 항목을 다른 날짜로 드래그하여 날짜를 변경할 수 있다.
- 데스크톱은 즉시 드래그하고 모바일은 길게 누른 후 드래그한다.
- 드래그 결과는 DB에 저장하여 PC와 모바일에서 동일하게 유지한다.
- 드래그 라이브러리는 SortableJS를 사용한다.
- 기존 예약 데이터와 개인 캘린더 데이터는 서로 연결하지 않는다.

## 2. 개발 목적

현재 예약테스트 기능에는 월 단위 달력, 이전·다음 달 이동, 오늘 표시, 날짜별 항목 출력과 반응형 디자인이 구현되어 있다. 이 화면 패턴을 활용해 로그인 회원이 일정과 할 일을 개인적으로 관리할 수 있는 `내 캘린더` 메뉴를 개발한다.

주요 목적은 다음과 같다.

1. 회원이 PC와 모바일에서 자신의 월간 일정을 확인한다.
2. 날짜를 선택해 일정을 빠르게 등록한다.
3. 드래그 앤 드롭으로 일정 순서와 날짜를 직관적으로 변경한다.
4. 개인 일정이 다른 회원이나 운영 통계 화면에 노출되지 않게 보호한다.
5. 기존 예약 기능에 영향을 주지 않는 독립 구조로 개발한다.

## 3. 기존 예약 달력 활용 범위

### 재사용할 요소

- 연·월 검증과 월별 날짜 계산 방식
- 이전 달과 다음 달 계산 방식
- 일요일부터 토요일까지의 7열 달력 구조
- 오늘, 일요일, 토요일의 시각적 구분
- `cal_navi`의 3열 중앙 정렬 월 이동 UI
- 현재 테마의 카드, 테두리, 보라색 포인트 디자인
- 데스크톱·태블릿·모바일 반응형 기준
- 월 범위 데이터를 한 번 조회한 뒤 날짜별로 묶어 출력하는 방식

### 재사용하지 않을 요소

- `wzp_room`, `wzp_room_status`, `wzp_booking` 등 객실·예약 테이블
- 예약의 `대기`, `완료`, `취소` 상태
- 결제, 객실 선택, 예약자 개인정보 처리
- 예약 가능 최대일과 자동 취소 로직
- 기존 `wz_calendar::holiday_list()`의 오래된 공휴일 데이터

개인 캘린더는 예약 플러그인을 직접 include하지 않는다. 필요한 날짜 계산과 UI 패턴만 새 플러그인에 구현한다.

## 4. 사용자와 권한

| 사용자 | 권한 |
|---|---|
| 비회원 | 접근 불가, 로그인 페이지로 안내 |
| 로그인 회원 | 자신의 일정·분류·개인 설정만 관리 |
| 관리자 | 기능 설정과 익명 통계만 관리, 개인 일정 내용은 기본적으로 조회 불가 |
| 최고관리자 | 설치·스키마 업데이트·장애 복구 수행 |

### 개인정보 보호 원칙

- 요청에서 전달된 `mb_id`를 신뢰하지 않는다.
- 현재 로그인 세션의 `$member['mb_id']`만 사용한다.
- 일정 ID로 조회해도 반드시 `mb_id`를 함께 조건에 넣는다.
- 다른 회원의 일정 ID에 접근하면 존재 여부를 알 수 없도록 404와 같은 응답을 사용한다.
- 운영 통계에 일정 제목, 본문과 장소를 포함하지 않는다.
- 서버 로그에 일정 본문을 기록하지 않는다.

## 5. MVP 기능 범위

### 개인 캘린더

- 현재 월 달력 표시
- 이전 달, 다음 달, 오늘로 이동
- 오늘 날짜 강조
- 날짜별 일정 표시
- 날짜 선택 시 해당 날짜 일정 목록 표시
- 개인 일정 등록, 상세 조회, 수정, 삭제
- 종일 일정과 시간 지정 일정
- 하루 일정과 여러 날짜 일정
- 개인 분류와 색상 설정
- 분류별 필터
- 일정이 많은 날짜의 `+N개` 표시
- PC·모바일 드래그 앤 드롭
- 같은 날짜 안의 순서 저장
- 다른 날짜로 이동한 결과 저장
- 저장 실패 시 원래 위치 복원
- 이동 직후 실행 취소

### 개인 설정

- 기본 일정 분류
- 날짜 셀 최대 표시 개수
- 모바일 드래그 사용 여부
- 한 주의 시작 요일은 MVP에서 일요일로 고정

### 운영 관리

- 캘린더 기능 사용 여부
- 회원당 일정 최대 개수
- 전체 사용 회원 수와 전체 일정 개수 통계
- DB 설치 상태와 스키마 버전 확인

관리자는 개인 일정 제목과 내용을 일괄 조회하거나 수정하는 화면을 제공하지 않는다.

## 6. MVP 제외 기능

- 공개 일정과 회원 간 공유
- 관리자 일정 등록 및 승인
- Google Calendar와 Outlook 동기화
- 이메일·문자·푸시 알림
- 복잡한 반복 일정 규칙
- 주간·일간 타임라인
- 여러 일정 동시 선택 및 다중 드래그
- 다른 회원에게 일정 양도
- 예약 현황과 개인 일정의 통합 표시

## 7. 사용자 화면

```text
내 캘린더
├─ 월 이동 및 도구
│  ├─ 이전 달
│  ├─ YYYY년 MM월
│  ├─ 다음 달
│  ├─ 오늘
│  └─ 일정 추가
├─ 개인 분류 필터
├─ 월간 달력
│  └─ 날짜 셀
│     ├─ 날짜
│     ├─ 드래그 가능한 일정
│     └─ +N개
└─ 선택 날짜 일정 목록
   ├─ 상세
   ├─ 수정
   └─ 삭제
```

### 일정 입력 항목

- 제목
- 개인 분류
- 시작일과 종료일
- 종일 여부
- 시작 시간과 종료 시간
- 설명
- 장소
- 외부 링크

### 모바일 원칙

- 달력은 화면 폭 안에 표시한다.
- 날짜 셀의 일정 제목은 한 줄 말줄임 처리한다.
- 전체 내용은 달력 아래의 선택 날짜 목록에서 제공한다.
- 일정의 드래그 손잡이를 길게 눌러 이동한다.
- 빈 날짜 셀도 충분한 드롭 영역을 제공한다.
- 드래그 중 화면 가장자리에 접근하면 자동 스크롤한다.

## 8. 드래그 앤 드롭 설계

### 적용 라이브러리

[SortableJS](https://github.com/SortableJS/Sortable)를 사용한다. 기존 달력 HTML을 유지하면서 터치 기기, 공유 목록, 드래그 손잡이, 모바일 지연 실행과 애니메이션을 적용할 수 있기 때문이다.

라이브러리는 외부 CDN에 의존하지 않고 고정 버전을 프로젝트 내부에 배포하며 라이선스 파일을 함께 보관한다.

### 권장 옵션

```javascript
new Sortable(dateEventList, {
    group: 'personal-calendar-events',
    draggable: '.wzc-event',
    handle: '.wzc-drag-handle',
    animation: 150,
    delay: 300,
    delayOnTouchOnly: true,
    touchStartThreshold: 5,
    fallbackTolerance: 5,
    ghostClass: 'wzc-event-ghost',
    chosenClass: 'wzc-event-chosen',
    dragClass: 'wzc-event-dragging',
    onEnd: saveEventMove
});
```

각 날짜의 일정 목록을 같은 `group`으로 초기화한다.

### 같은 날짜 안의 순서 변경

```text
일정 드래그
  → 같은 날짜의 새 위치에 드롭
  → 화면에 임시 반영
  → 순서 저장 API 호출
  → 성공: 확정
  → 실패: 이전 순서 복원
```

### 다른 날짜로 이동

```text
일정 드래그
  → 다른 날짜 셀에 드롭
  → 대상 날짜와 순서 계산
  → 날짜 이동 API 호출
  → 성공: 확정 및 실행 취소 표시
  → 실패: 원래 날짜와 위치 복원
```

### 여러 날짜 일정

- 다른 날짜로 이동하면 기존 기간 길이를 유지한다.
- 예: 8월 10~12일 일정을 8월 15일로 옮기면 8월 15~17일이 된다.
- 기간 늘이기와 줄이기는 MVP에서 수정 폼으로 처리한다.
- 날짜별 표시 순서는 별도의 일정 순서 테이블에 저장한다.

### 모바일 충돌 방지

- 일정 제목을 짧게 누르면 상세 화면을 연다.
- 드래그 손잡이를 약 300ms 길게 눌러야 이동을 시작한다.
- 짧은 터치와 작은 흔들림은 일반 스크롤로 처리한다.
- 드래그 중 선택 일정과 드롭 대상 날짜를 강조한다.
- 모바일 브라우저의 전체 페이지 스크롤을 차단하지 않는다.

### 접근성 대체 기능

드래그만으로 기능을 제공하지 않는다. 각 일정의 더보기 메뉴에 다음 조작을 제공한다.

- 날짜 변경
- 위로 이동
- 아래로 이동
- 맨 위로 이동

드래그와 버튼 조작은 같은 서버 API를 사용한다.

## 10. 메뉴 연결

1. `calendar` 게시판을 생성한다.
2. 게시판 목록 권한을 로그인 회원 레벨 이상으로 설정한다.
3. 게시판 스킨을 새 `calendar` 스킨으로 지정한다.
4. `list.skin.php`에서 개인 캘린더 플러그인을 불러온다.
5. 사이트 메뉴에 `/calendar` 링크를 등록한다.
6. `is_menu_active()`로 1depth와 2depth 메뉴를 강조한다.
7. 플러그인에서도 비회원 접근을 다시 검사한다.

## 11. 데이터 모델

모든 새 테이블은 `InnoDB`와 `utf8mb4`를 사용한다.

### `g5_wzc_category`

| 필드 | 형식 | 설명 |
|---|---|---|
| `wc_ix` | INT, PK, AI | 분류 ID |
| `mb_id` | VARCHAR(20), INDEX | 소유 회원 ID |
| `wc_name` | VARCHAR(50) | 분류명 |
| `wc_color` | CHAR(7) | `#RRGGBB` 색상 |
| `wc_use` | TINYINT | 사용 여부 |
| `wc_sort` | SMALLINT | 표시 순서 |
| `wc_created_at` | DATETIME | 생성일시 |
| `wc_updated_at` | DATETIME | 수정일시 |

권장 제약 조건: `UNIQUE (mb_id, wc_name)`

### `g5_wzc_config`

| 필드 | 형식 | 설명 |
|---|---|---|
| `wcf_ix` | TINYINT, PK | 설정 행 ID |
| `wcf_use` | TINYINT | 전체 기능 사용 여부 |
| `wcf_max_events` | INT | 회원당 최대 일정 수 |
| `wcf_schema_version` | INT | DB 스키마 버전 |
| `wcf_updated_at` | DATETIME | 수정일시 |

### 월간 조회 조건

```sql
WHERE mb_id = :session_mb_id
  AND we_deleted_at IS NULL
  AND we_start_date <= :month_end
  AND we_end_date >= :month_start
ORDER BY we_start_date, we_start_time, we_ix
```

`:session_mb_id`는 요청 값이 아니라 로그인 세션에서 가져온다.

### 권장 인덱스

- `g5_wzc_event (mb_id, we_deleted_at, we_start_date, we_end_date)`
- `g5_wzc_event (mb_id, wc_ix)`
- `g5_wzc_event_order (mb_id, wo_date, wo_sort)`
- `g5_wzc_category (mb_id, wc_use, wc_sort)`

## 12. 서버 처리 흐름

### 월간 달력

```text
GET /calendar?sch_year=2026&sch_month=8&sch_day=2026-08-31
  → 로그인 검사
  → 날짜 검증
  → 월 시작일·종료일 계산
  → 현재 mb_id의 일정만 조회
  → 날짜별 일정과 순서 구성
  → 개인 달력 렌더링
```

### 일정 날짜 이동

```text
POST ajax.event.move.php
  event_id, source_date, target_date, target_index, version, csrf_token
  → 로그인·CSRF 검사
  → event_id + 현재 mb_id로 소유권 검사
  → 버전 충돌 검사
  → 기존 기간 길이를 유지해 날짜 계산
  → 대상 날짜 순서 재정렬
  → 트랜잭션 저장
  → 새 날짜·순서·version 반환
```

### 같은 날짜 순서 변경

```text
POST ajax.event.order.php
  date, ordered_event_ids[], csrf_token
  → 모든 일정 ID의 현재 회원 소유권 검사
  → 해당 날짜에 표시되는 일정인지 검사
  → event_order를 트랜잭션으로 저장
```

순서 배열에 다른 회원의 일정 ID가 하나라도 포함되면 전체 요청을 거부한다.

## 13. 동시 수정과 오류 복구

- 일정마다 `we_version`을 저장한다.
- 저장할 때 클라이언트가 알고 있는 버전을 전송한다.
- 서버는 버전이 일치할 때만 저장하고 1 증가시킨다.
- 다른 기기에서 먼저 수정했다면 HTTP 409를 반환한다.
- 클라이언트는 변경을 되돌리고 최신 데이터를 다시 불러온다.
- 네트워크 오류에는 재시도 기능을 제공한다.
- 이동 성공 후 일정 시간 동안 실행 취소를 표시한다.
- 실행 취소에도 소유권과 버전 검사를 적용한다.

## 14. 입력 검증과 보안

- 비회원 요청은 로그인 안내로 처리한다.
- 연도, 월과 날짜를 서버에서 검증한다.
- 시작일은 종료일보다 늦을 수 없다.
- 제목과 장소 출력에는 HTML 이스케이프를 적용한다.
- 본문은 GNU Board의 HTML 정제 방식을 사용한다.
- 외부 링크는 `http`와 `https`만 허용한다.
- 색상은 `^#[0-9A-Fa-f]{6}$`만 허용한다.
- 정수 캐스팅과 `sql_escape_string()`을 적용한다.
- 모든 저장·이동·삭제 요청은 CSRF 토큰을 검사한다.
- 삭제와 이동은 GET으로 처리하지 않는다.
- 모든 일정·분류 쿼리에 세션 `mb_id`를 포함한다.
- AJAX 응답에 PHP 경고와 SQL 오류 원문을 노출하지 않는다.

## 15. DB 설치와 업데이트

1. 최고관리자만 실행할 수 있는 설치 화면을 제공한다.
2. `CREATE TABLE IF NOT EXISTS`로 최초 설치를 처리한다.
3. 사용자 페이지에서는 `ALTER TABLE`을 실행하지 않는다.
4. `wcf_schema_version`으로 마이그레이션 버전을 관리한다.
5. 실패하면 트랜잭션을 롤백하고 관리자에게만 오류를 보여준다.
6. 스키마 변경 전 DB 백업을 안내한다.

## 17. 테스트 계획

### 회원 데이터 격리

- 회원 A의 일정이 회원 B 달력에 표시되지 않음
- 회원 B가 회원 A 일정 ID로 상세 조회·수정·삭제·이동 불가
- 다른 회원의 분류 ID를 사용할 수 없음
- 요청 배열에 다른 회원 일정 ID가 섞이면 전체 거부
- 로그아웃 후 뒤로가기로 일정 내용이 다시 노출되지 않음

### 달력 기능

- 1월과 12월의 연도 경계 이동
- 윤년 2월 29일
- 잘못된 날짜 파라미터 처리
- 오늘 날짜 강조
- 하루·종일·시간·여러 날짜 일정 표시
- 분류 필터와 `+N개` 표시

### 드래그

- 같은 날짜의 순서 변경
- 빈 날짜와 일정이 있는 날짜로 이동
- 여러 날짜 일정의 기간 유지 이동
- 빠른 연속 드래그
- 네트워크 실패 시 원복
- 동시 수정 시 HTTP 409 처리
- 실행 취소 후 원래 날짜와 순서 복원

### 모바일

- Android Chrome 길게 누르기와 이동
- iOS Safari 길게 누르기와 이동
- 일반 스크롤이 드래그로 오인되지 않음
- 제목 터치 시 상세 열기
- 화면 가장자리 자동 스크롤
- 390px 화면에서 드롭 대상 확인

### 회귀

- 예약 달력 월 이동
- 객실 선택과 다음 단계 이동
- 예약 대기·완료·취소 표시
- 관리자 예약 상태 변경
- 헤더와 사이드 메뉴 활성 표시

## 18. 인수 기준

- 로그인 회원이 자신의 일정과 분류만 관리할 수 있다.
- 회원 간 일정 데이터가 완전히 격리된다.
- 관리자가 개인 일정 내용을 일반 관리 화면에서 열람하지 않는다.
- 월 이동, 오늘 이동과 일정 상세가 정상 작동한다.
- 같은 날짜 순서 변경과 다른 날짜 이동이 DB에 저장된다.
- Android와 iOS에서 길게 누른 후 드래그가 작동한다.
- 저장 실패 시 화면이 원래 상태로 복원된다.
- 키보드로 날짜와 순서를 변경할 수 있다.
- 모바일 390px에서 달력과 일정 목록을 사용할 수 있다.
- 기존 예약 테이블과 상태값을 변경하지 않는다.
- 주요 페이지 HTTP 200, PHP 문법과 서버 로그 검사를 통과한다.
