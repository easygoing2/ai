# 캘린더 메뉴 개발 기획서

- 작성일: 2026-08-30
- 대상 시스템: GNU Board + `UXC_BaseCamp` 테마
- 기준 기능: `plugin/wz.booking.pension`의 실시간 예약 달력
- 문서 상태: 초안(MVP 개발 기준)

## 1. 기획 배경

현재 예약테스트 기능에는 월 단위 달력, 이전·다음 달 이동, 오늘 표시, 날짜별 객실 상태 출력, 반응형 화면이 구현되어 있다. 
이 화면 패턴을 기반으로 사이트의 일정·행사·공지 등을 월별로 확인할 수 있는 별도의 **캘린더 메뉴**를 개발한다.

캘린더는 예약 기능과 비슷한 화면을 사용하지만 데이터의 의미와 관리 흐름이 다르다. 
예약 데이터에 캘린더 일정을 직접 섞으면 예약 상태 변경, 자동 취소, 객실 관리 로직과 충돌할 수 있으므로 일정 데이터는 별도 플러그인과 별도 테이블로 분리한다.

### 기본 가정

이 문서에서 “캘린더 메뉴”는 다음 기능을 의미한다.

- 사용자가 사이트 메뉴에서 월간 일정을 조회한다.
- 관리자가 일정과 일정 분류를 등록·수정·삭제한다.
- 일정은 하루 또는 여러 날짜에 걸쳐 등록할 수 있다.
- 예약 달력의 레이아웃과 톤앤매너는 활용하지만 예약 신청 기능은 포함하지 않는다.
- 기존 실시간 예약 기능은 그대로 유지한다.

예약 현황을 새 캘린더에 함께 표시하는 기능은 MVP 이후의 선택 기능으로 분리한다.

## 2. 기존 예약 달력 분석

### 현재 진입 구조

```text
게시판 메뉴 /reservation
  └─ skin/board/pensionstatus/list.skin.php
      └─ plugin/wz.booking.pension/status.index.php
          ├─ calendar.skin.php
          ├─ step.1.skin.php
          ├─ step.2.skin.php
          └─ 예약 확인 화면
```

### 재사용할 요소

- 연·월 입력 검증과 월별 날짜 계산 방식
- 이전 달과 다음 달 계산 방식
- 일요일부터 토요일까지의 7열 달력 구조
- 오늘, 일요일, 토요일의 시각적 구분
- `cal_navi`의 월 이동 UI
- 현재 테마와 맞춘 카드, 테두리, 보라색 포인트 디자인
- 데스크톱·모바일 반응형 기준
- 날짜 범위로 데이터를 한 번에 조회한 후 날짜별로 묶어 출력하는 방식

### 직접 재사용하지 않을 요소

- `wzp_room`, `wzp_room_status`, `wzp_booking` 등 객실·예약 테이블
- `대기`, `완료`, `취소` 같은 예약 전용 상태값
- 예약 가능 최대일, 당일 예약 가능 여부, 자동 예약 취소 로직
- 결제 및 예약자 개인정보 처리 흐름
- 기존 `wz_calendar::holiday_list()`의 음력 공휴일 데이터

기존 음력 공휴일 목록은 2016~2017년에 고정되어 있어 범용 캘린더에서 사용하기 어렵다. MVP에서는 법정 공휴일을 별도 데이터로 관리하거나 공휴일 표시를 제외하고, 추후 공공데이터 API 또는 연도별 데이터 갱신 방식을 검토한다.

## 3. 목표와 비목표

### 목표

1. 사이트 이용자가 월별 일정을 빠르게 파악할 수 있다.
2. 관리자가 개발자 도움 없이 일정과 분류를 관리할 수 있다.
3. 기존 예약 달력과 동일한 사이트 톤앤매너를 유지한다.
4. 일정 데이터와 예약 데이터를 분리해 기능 간 장애 전파를 막는다.
5. 추후 주간 보기, 반복 일정, 예약 현황 연동으로 확장할 수 있다.

### MVP에서 제외할 기능

- Google Calendar, Outlook 등 외부 캘린더 동기화
- 사용자 개인 캘린더와 비공개 일정
- 일반 회원의 일정 등록 및 승인 요청
- 이메일·문자·푸시 알림
- 복잡한 반복 일정 규칙
- 드래그 앤 드롭 일정 변경
- 예약 달력에 대한 쓰기 또는 예약 상태 변경

## 4. 사용자와 권한

| 사용자 | 권한 |
|---|---|
| 비회원 | 공개 일정의 월간 보기와 상세 보기 |
| 로그인 회원 | MVP에서는 비회원과 동일 |
| 캘린더 관리자 | 일정·분류 등록, 수정, 숨김, 삭제 |
| 최고관리자 | 환경설정, 권한 설정, DB 설치·업데이트 |

MVP에서는 프런트 일정 등록을 제공하지 않는다. 관리자 페이지의 GNU Board 권한 검사와 폼 토큰 검사를 반드시 사용한다.

## 5. MVP 기능 범위

### 사용자 화면

- 현재 월 달력 표시
- 이전 달, 다음 달, 오늘로 이동
- 일·월·화·수·목·금·토 요일 표시
- 오늘 날짜 강조
- 날짜별 일정 제목 표시
- 분류별 색상 표시
- 일정이 많은 날짜는 정해진 개수만 표시하고 `+N개` 제공
- 날짜 선택 시 해당 날짜 일정 목록 표시
- 일정 제목 선택 시 상세 화면 이동
- 일정 분류 필터
- 공개 예정·비공개 일정 제외
- 모바일에서 가로 스크롤 없이 주요 정보를 확인할 수 있는 반응형 화면
- 키보드 탐색과 `aria-label`을 적용한 월 이동 버튼

### 관리자 화면

- 일정 목록 검색 및 기간·분류·상태 필터
- 일정 등록, 수정, 복사, 삭제
- 공개, 숨김, 임시저장 상태 관리
- 종일 일정과 시간 지정 일정
- 단일 날짜와 여러 날짜에 걸친 일정
- 제목, 설명, 장소, 외부 링크 입력
- 일정 분류 등록, 수정, 노출 순서, 색상 설정
- 메인 달력 기본 표시 개수 등 환경설정

## 7. UX·디자인 원칙

- 예약 달력의 `cal_navi`, 7열 달력, 오늘 표시 스타일을 기반으로 한다.
- 새 기능의 CSS는 `.wzc-calendar` 아래로 한정해 예약 달력 및 테마 CSS와 충돌하지 않게 한다.
- 연·월 제목은 좌우 버튼과 독립적인 3열 Grid로 정확히 중앙 정렬한다.
- 요일 헤더는 가로·세로 중앙 정렬한다.
- 일요일은 빨간색 계열, 토요일은 보라색 계열을 유지한다.
- 일정 분류 색상은 제목 앞의 작은 점 또는 왼쪽 선으로 표현하고, 텍스트 대비를 확보한다.
- 색상만으로 상태나 분류를 전달하지 않고 분류명 텍스트를 함께 제공한다.
- 날짜 셀 전체를 링크로 만들지 않고 날짜 버튼과 일정 링크를 분리한다.
- 모바일에서는 일정 제목을 한 줄 말줄임하고 선택 날짜의 전체 일정은 달력 아래에서 제공한다.

## 8. 권장 기술 구조

예약 플러그인에 새 코드를 추가하지 않고 독립된 `wz.calendar` 플러그인으로 구성한다.

```text
plugin/wz.calendar/
├─ config.php
├─ calendar.lib.php
├─ calendar.index.php
├─ calendar.month.skin.php
├─ event.list.skin.php
├─ event.view.skin.php
├─ style.css
└─ install.sql 또는 install.php

skin/board/calendar/
└─ list.skin.php

adm/wz_calendar_admin/
├─ _common.php
├─ wzc_event_list.php
├─ wzc_event_form.php
├─ wzc_event_update.php
├─ wzc_category_list.php
├─ wzc_category_update.php
├─ wzc_config.php
└─ wzc_config_update.php

adm/admin.menu790.php
```

### 게시판 및 메뉴 연결

1. `calendar` 게시판을 생성한다.
2. 게시판 스킨을 새 `calendar` 스킨으로 설정한다.
3. `list.skin.php`에서 `plugin/wz.calendar/calendar.index.php`를 불러온다.
4. 관리자 메뉴 설정에서 `/calendar`를 1depth 또는 2depth 메뉴로 등록한다.
5. 기존 메뉴 활성화 함수 `is_menu_active()`를 사용해 현재 메뉴를 강조한다.

### 달력 유틸리티

`wz_calendar`를 예약 플러그인에서 직접 include하지 않는다. 예약 기능의 회귀 위험을 줄이기 위해 다음 기능만 검토하여 새 `WzcCalendar` 클래스로 작성한다.

- 연·월 검증
- 월의 첫 요일과 마지막 날짜 계산
- 이전·다음 연월 계산
- 오늘과 선택 날짜 판정
- 달력 주 단위 배열 생성

향후 예약 달력까지 공통 컴포넌트로 통합할 때는 별도 리팩터링 작업과 예약 회귀 테스트를 진행한다.

### 조회 규칙

월 범위와 겹치는 공개 일정은 다음 조건으로 한 번에 조회한다.

```sql
WHERE we_status = 'published'
  AND we_start_date <= :month_end
  AND we_end_date >= :month_start
ORDER BY we_is_featured DESC, we_sort ASC, we_start_time ASC, we_ix ASC
```

여러 날짜에 걸친 일정은 조회 후 PHP에서 각 날짜에 배치한다. 일정 기간은 사용자 화면에서 시작일과 종료일을 모두 포함하는 것으로 정의한다.

### 인덱스 권장안

- `g5_wzc_event (we_status, we_start_date, we_end_date)`
- `g5_wzc_event (wc_ix, we_status)`
- `g5_wzc_event (mb_id)`
- `g5_wzc_category (wc_use, wc_sort)`

## 10. 요청과 처리 흐름

### 월간 달력

```text
GET /calendar?sch_year=2026&sch_month=8&sch_day=2026-08-30
  → 연·월·선택일 검증
  → 해당 월의 시작일·종료일 계산
  → 공개 일정 범위 조회 1회
  → 날짜별 일정 배열 구성
  → 달력 렌더링
```

초기 MVP는 기존 예약 달력처럼 GET 방식의 페이지 이동을 사용한다. 기능이 안정된 후 월 부분만 AJAX로 바꾸더라도 URL 쿼리는 계속 갱신해 새로고침, 뒤로가기, 링크 공유가 가능해야 한다.

### 일정 등록

```text
관리자 등록 폼
  → 관리자 권한 및 토큰 검사
  → 제목·날짜·상태·색상·URL 검증
  → 시작일이 종료일보다 늦지 않은지 검사
  → 종일 일정이면 시간 필드 NULL 처리
  → INSERT
  → 일정 목록 또는 수정 화면으로 이동
```

## 11. 입력 검증과 보안

- `sch_year`는 4자리 숫자와 허용 연도 범위를 검사한다.
- `sch_month`는 1~12만 허용한다.
- 날짜는 정규식만 사용하지 않고 `checkdate()`로 실제 날짜인지 확인한다.
- 일정 시작일은 종료일보다 늦을 수 없다.
- 제목과 장소는 출력 시 `get_text()` 또는 `htmlspecialchars()`를 적용한다.
- 본문은 GNU Board 에디터 및 기존 HTML 정제 방식을 사용한다.
- 외부 링크는 `http`와 `https` 스킴만 허용한다.
- 분류 색상은 `^#[0-9A-Fa-f]{6}$` 형식만 허용한다.
- SQL 입력은 정수 캐스팅과 `sql_escape_string()`을 적용한다.
- 모든 관리자 변경 요청은 `auth_check_menu()`와 CSRF 폼 토큰을 검사한다.
- 삭제는 GET 링크가 아니라 POST 요청으로 처리한다.
- 관리자 권한이 없는 사용자는 임시저장·숨김 일정을 조회할 수 없다.

## 12. DB 설치 및 업데이트 전략

현재 예약 플러그인은 일부 관리자 페이지 진입 시 테이블을 생성·변경한다. 새 캘린더는 설치와 일반 화면 실행을 분리한다.

권장 방식은 다음과 같다.

1. 최고관리자만 실행 가능한 설치 또는 환경설정 화면을 제공한다.
2. `CREATE TABLE IF NOT EXISTS`를 사용해 최초 설치를 멱등하게 처리한다.
3. `wcf_schema_version`을 저장한다.
4. 버전별 마이그레이션 함수를 순서대로 실행한다.
5. 사용자 달력 페이지에서는 `ALTER TABLE`을 실행하지 않는다.
6. 설치 실패 시 실행 SQL과 오류를 관리자에게만 보여준다.

## 13. 개발 단계와 예상 일정

1명의 개발자가 기존 프로젝트 구조를 이해하고 있다는 기준으로 약 9~12 작업일을 예상한다.

| 단계 | 작업 | 예상 |
|---|---|---:|
| 1 | 요구사항 확정, 메뉴·URL·권한 결정 | 0.5일 |
| 2 | 플러그인 골격, 설정, DB 설치/마이그레이션 | 1.5일 |
| 3 | 분류 및 일정 관리자 CRUD | 2일 |
| 4 | 월간 달력 조회와 날짜별 일정 배치 | 2일 |
| 5 | 일정 상세, 필터, 선택 날짜 목록 | 1.5일 |
| 6 | UXC 디자인 및 모바일 대응 | 1.5일 |
| 7 | 보안, 접근성, 예외 처리 | 1일 |
| 8 | 통합·회귀 테스트 및 배포 준비 | 1~2일 |

### 단계별 완료 조건

#### 1단계: 기반 구축

- 캘린더 게시판과 메뉴 URL이 정상 연결된다.
- 설치 화면에서 필요한 테이블이 생성된다.
- 중복 실행해도 오류나 데이터 손실이 없다.

#### 2단계: 관리자 기능

- 분류와 일정을 등록·수정·숨김·삭제할 수 있다.
- 잘못된 날짜 범위와 권한 없는 요청이 차단된다.

#### 3단계: 사용자 달력

- 월 이동과 오늘 이동이 정상 작동한다.
- 단일·다중 날짜 일정이 정확한 날짜에 표시된다.
- 공개 일정만 표시된다.

#### 4단계: 품질 확보

- 데스크톱과 모바일에서 레이아웃이 깨지지 않는다.
- 기존 예약테스트 기능에 회귀 오류가 없다.
- PHP 경고, 500 오류, 신규 서버 로그 오류가 없다.

## 14. 테스트 계획

### 기능 테스트

- 1월에서 이전 달 이동 시 전년도 12월 표시
- 12월에서 다음 달 이동 시 다음 연도 1월 표시
- 윤년 2월 29일 표시
- 잘못된 연·월·날짜 파라미터의 기본값 처리
- 오늘 날짜 표시
- 일요일·토요일 스타일 표시
- 하루 일정, 종일 일정, 시간 일정 표시
- 월을 넘는 다중 날짜 일정 표시
- 일정 0개, 1개, 최대 표시 수 초과 상태
- 분류 필터 적용과 해제
- 공개·숨김·임시저장 상태별 노출
- 일정 상세와 달력 복귀 시 기존 월 유지

### 관리자·보안 테스트

- 비관리자의 관리자 URL 접근 차단
- CSRF 토큰 없는 등록·수정·삭제 차단
- 제목·본문 XSS 입력 정제
- 비정상 외부 URL 차단
- 시작일이 종료일보다 늦은 일정 차단
- 사용 중인 분류 삭제 정책 확인
- 동시에 같은 일정을 수정할 때 최종 저장 정책 확인

### 반응형·접근성 테스트

- 1440px, 1024px, 768px, 390px 화면 확인
- 월 이동 버튼 키보드 포커스와 스크린리더 이름 확인
- 일정 링크의 포커스 순서 확인
- 색상 대비 및 다크모드 확인
- 일정 제목이 긴 경우 말줄임과 상세 제목 제공

### 회귀 테스트

- 예약 달력 월 이동
- 객실 선택과 다음 단계 이동
- 예약 대기·완료·취소 표시
- 관리자 예약 상태 변경
- 헤더와 사이드 메뉴 활성 표시

## 15. 인수 기준

다음 조건을 모두 만족하면 MVP 완료로 판단한다.

- 관리자가 분류와 일정을 등록·수정·삭제할 수 있다.
- 공개 일정이 지정된 모든 날짜에 정확히 표시된다.
- 월 이동, 오늘 이동, 일정 상세 이동이 정상 작동한다.
- 예약 기능의 테이블과 상태값을 변경하지 않는다.
- 모바일 390px에서 달력과 일정 목록을 사용할 수 있다.
- 사용자 입력으로 XSS나 임의 SQL이 실행되지 않는다.
- 잘못된 요청이 500 오류가 아닌 안내 또는 안전한 기본 화면으로 처리된다.
- PHP 문법 검사, 주요 HTTP 200 응답, 서버 오류 로그 검사를 통과한다.

## 16. 배포 계획

1. 운영 DB 백업
2. 플러그인·스킨·관리자 파일 배포
3. 최고관리자로 DB 설치 및 스키마 버전 확인
4. 기본 분류 2~3개 등록
5. 테스트 일정으로 관리자 CRUD 검증
6. 비공개 메뉴 URL에서 사용자 화면 검증
7. 사이트 메뉴에 캘린더 공개
8. 예약테스트 및 주요 게시판 회귀 확인
9. 배포 후 PHP/nginx 오류 로그 모니터링

문제가 발생하면 메뉴 노출을 먼저 해제한다. 캘린더 데이터가 예약 데이터와 분리되어 있으므로 예약 기능은 계속 사용할 수 있어야 한다.

## 17. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 예약 플러그인 코드를 직접 수정해 회귀 발생 | 독립 플러그인으로 개발하고 공통화는 추후 진행 |
| 일정이 많아 달력 셀이 과도하게 길어짐 | 셀 표시 개수 제한 및 `+N개` 목록 제공 |
| 다중 날짜 일정 조회 누락 | 월 범위 겹침 조건과 경계일 테스트 적용 |
| 분류 색상으로 인한 가독성 저하 | 색상 형식·대비 검사와 텍스트 분류명 병행 |
| 공휴일 정보가 오래되거나 부정확함 | MVP 분리, 데이터 출처와 갱신 방식 확정 후 적용 |
| 관리자 페이지 진입 시 임의 DB 변경 | 명시적 설치·버전 마이그레이션으로 분리 |
| 모바일에서 일정 정보가 잘림 | 셀에는 요약, 하단 선택 날짜 목록에는 전체 정보 제공 |

## 19. 개발 전 확정할 사항

아래 항목은 구현 시작 전에 결정하면 재작업을 줄일 수 있다.

1. 캘린더의 주 용도: 행사, 휴무일, 교육, 내부 일정 중 무엇인지
2. 일반 회원에게 일정 등록 권한을 제공할지
3. 일정 상세를 새 페이지로 열지, 달력 아래 패널로 보여줄지
4. 공휴일 표시가 MVP에 반드시 필요한지
5. 예약 현황을 같은 캘린더에 함께 표시할지
6. 관리자 외에 일정 담당자 권한을 별도로 둘지
7. 여러 날짜 일정과 시간 지정 일정이 모두 필요한지
8. 메뉴 위치와 메뉴명: `캘린더`, `일정`, `행사일정` 중 선택

현재 권장 기본값은 **관리자만 등록**, **월간 보기 + 하단 일정 목록 + 상세 페이지**, **공휴일 연동 제외**, **예약 현황 분리**, **메뉴명 `캘린더`**이다.
